# SF CodeIntel agent instructions

Start with the [governance register](docs/governance/SF-CI-GOV-001.md). Use its authority routing to find the clauses that govern the assigned work. Verify the exact revision, adoption record and applicable approvals before treating a document as binding. Raise authority conflicts with the project owner.

The owner controls scope, budgets and gate acceptance. Architecture agents prepare technical decisions for review. Implementation and qualification agents work within approved assignments. The execution operator verifies admission and enforces the run limits. Independent reviewers check the exact candidate and its evidence. Keep authoring and independent acceptance separate.

The current scope is documentation bootstrap and review. P0-A requires a recorded admission under the applicable qualification assignment and separate execution authorization. P0-B and P1 implementation require their own approvals. Until those gates are met, keep work documentation-only. Backend installation, acquisition, execution, selection and application scaffolding are outside this bootstrap.

Use an issue, branch and PR for authorized material changes once tracking and hosting are established. Record unresolved evidence and request independent review. Merge requires explicit owner authorization.
