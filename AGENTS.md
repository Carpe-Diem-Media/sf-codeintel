# SF CodeIntel agent instructions

Start with the [governance register](docs/governance/SF-CI-GOV-001.md). Use its assignment routing to identify the exact applicable revisions, adoption records and permissions. Stop affected work and route missing or conflicting authority to the accountable authority.

The project owner designates the persistent Lead Orchestrator as accountable adoption and technical acceptance authority within the approved MVP until the owner explicitly supersedes or revokes the designation. Verify the trusted mandate and applicable scope in [GOV §4.1](docs/governance/SF-CI-GOV-001.md#41-standing-owner-directive). Keep substantive authorship separate from independent review and accountable acceptance. Apply the separate execution and integration gates.

Keep bootstrap work documentation-only. P0-A requires verified admission, execution operator ratification and bounded execution permission. P0-B is optional and requires a separate grant to run. If the applicable P0 gate proceeds without P0-B, the accountable authority must explicitly defer it to P1. P1 dispatch requires the applicable P0 exit, an accepted viable backend decision, an accepted P1 design and a bounded P1 execution grant. See [phase gates](docs/governance/SF-CI-GOV-001.md#6-current-gate--p0-a-admission-and-bounded-qualification). For the synthetic lexical increment, verify [SFCI-16 activation](docs/governance/sfci-2-baseline-adoption.md#sfci-16-conditional-sequencing-applicability) before applying the [sequencing exception](docs/governance/SF-CI-SEQ-001.md). For SFCI-19, verify [SFCI-18 activation](docs/governance/sfci-2-baseline-adoption.md#sfci-18-conditional-sequencing-applicability) before applying the proposed sequencing supplement. For SFCI-21, verify [SFCI-20 activation and reconciliation](docs/governance/sfci-2-baseline-adoption.md#sfci-20-conditional-sequencing-applicability) before applying the [SFCI-20 sequencing supplement](docs/governance/SF-CI-SEQ-001-SFCI-10.md).

Follow [artifact persistence and restart recovery](docs/governance/SF-CI-GOV-001.md#72-artifact-persistence-and-restart-recovery) when planning, authoring, provisioning, executing, resuming, handing off or reviewing work. Identify persistent locations before substantive work. Checkpoint important work as it progresses and reconcile state after an interruption before continuing.

Use an issue-linked branch and PR for authorized material changes. Follow the [assignment and review process](docs/governance/SF-CI-GOV-001.md#7-agent-entry-point-and-assignment-routing) and record unresolved findings. The [owner's standing directive](docs/governance/SF-CI-GOV-001.md#41-standing-owner-directive) authorizes the Lead Orchestrator to merge routine PRs within scope after [independent final candidate review and a separate integration check](docs/governance/SF-CI-GOV-001.md#8-verification-independent-review-and-merge-boundary).
